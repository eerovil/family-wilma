# WilmAI homework and lesson-note support

Research date: 2026-09-15. Scope: the latest npm releases and upstream's default branch, using only npm and the official `aikarjal/wilmai` repository. The repository had no existing `docs/research/` convention, so this note uses the requested path.

## Executive conclusion

Yes: `@wilm-ai/wilma-client` exposes homework as `client.overview.get().homework`, typed as `HomeworkItem[]`. It reads authenticated, student-prefixed `GET /overview` JSON and extracts non-empty `Groups[].Homework[]` entries. There is no dedicated `client.homework` method and no supported homework create/update/delete operation. The wider WilmAI CLI exposes the same data as `wilma homework list` and includes recent homework in `wilma summary` ([client implementation, lines 230-235](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/client.ts#L230-L235); [CLI implementation, lines 1487-1503](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-cli/src/index.ts#L1487-L1503); [CLI README, lines 21-47](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-cli/README.md#L21-L47)).

Related "lesson notes" are separate, read-only attendance markings: `client.attendance.list({ date? })` returns `LessonNote[]` from authenticated `GET /attendance/view[?date=YYYY-MM-DD]`. The implementation does not combine these markings with homework or expose a broader lesson-diary object ([client implementation, lines 203-215](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/client.ts#L203-L215); [parser description, lines 4-20](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/parsers/attendance.ts#L4-L20); [extracted fields, lines 99-114](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/parsers/attendance.ts#L99-L114)).

## Public API, types, and routes

### Homework

- Public call: `await client.overview.get()`. Its declared return is `Promise<OverviewData>`; `OverviewData.homework` is `HomeworkItem[]` ([client implementation, lines 230-235](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/client.ts#L230-L235); [types, lines 129-145](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/types.ts#L129-L145)). `HomeworkItem` and `OverviewData` are package-root type exports ([exports, lines 1-20](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/index.ts#L1-L20)).
- `HomeworkItem` fields are `date`, `subject`, `subjectCode`, `homework`, `teacher`, and `teacherCode`; all are strings, with `date` documented as `YYYY-MM-DD` ([types, lines 129-137](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/types.ts#L129-L137)).
- Wilma transport: authenticated HTTP `GET /!<studentNumber>/overview` when a student number is configured, otherwise `GET /overview`. `overview.get()` calls `session.get('/overview')`; `get()` fixes the method to `GET`, and session prefixing inserts `!<studentNumber>` ([client, lines 230-235](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/client.ts#L230-L235); [session prefixing, lines 42-53](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/session.ts#L42-L53); [HTTP helpers, lines 173-203](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/session.ts#L173-L203)).
- Source shape: homework comes from `Groups[].Homework[]`, whose recognized raw fields are `RowNumber`, `Date`, and `Homework`; subject and first-teacher metadata come from the containing group ([raw types, lines 43-57](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/parsers/overview.ts#L43-L57)). Parsing drops blank homework text, normalizes CRLF, omits `RowNumber`, and sorts descending by the returned date string ([parser, lines 230-258](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/parsers/overview.ts#L230-L258)).
- Ecosystem CLI: `wilma homework list [--limit 10] [--student ...] [--all-students] [--json]` calls `overview.get()`, takes the first `limit` items, and emits either the array or text. Multi-student mode logs in per student and returns each student's items ([CLI README, lines 44-47](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-cli/README.md#L44-L47); [single-student implementation, lines 1487-1503](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-cli/src/index.ts#L1487-L1503); [multi-student implementation, lines 2264-2275](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-cli/src/index.ts#L2264-L2275)).

### Attendance / lesson notes

- Public call: `await client.attendance.list({ date?: 'YYYY-MM-DD' })`, returning `Promise<LessonNote[]>`. `LessonNote` has `date`, nullable `start`/`end`, `subject`, `typeLabel`, `typeClass`, and `teacher`, and is exported at the package root ([client, lines 203-215](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/client.ts#L203-L215); [type, lines 147-161](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/types.ts#L147-L161); [exports, lines 1-20](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/index.ts#L1-L20)).
- Wilma transport: authenticated HTTP `GET /!<studentNumber>/attendance/view?date=YYYY-MM-DD` (or the unprefixed equivalent/no query). The parser scrapes an HTML table, derives times from header/cell spans, and recognizes event cells by `at-tpN` CSS classes ([client, lines 203-215](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/client.ts#L203-L215); [parser, lines 20-57](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/parsers/attendance.ts#L20-L57)).
- Ecosystem CLI: `wilma attendance list [--date ...] [--student ...] [--all-students] [--json]` shows these lesson markings; the docs describe them as type labels, subjects, and teachers ([CLI README, lines 70-75](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-cli/README.md#L70-L75)).

## Read/write determination

The concrete homework and lesson-note features are read-only. Their exposed high-level methods issue only `GET` requests, and the CLI offers only `list`/summary commands. No exposed method or concrete implementation in this release creates, edits, acknowledges, completes, or deletes homework or lesson notes ([client routes, lines 203-235](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/client.ts#L203-L235); [CLI command list, lines 19-82](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-cli/README.md#L19-L82)).

`WilmaSession` is exported and has a generic `post()` helper, but that does **not** establish writable homework support: upstream provides no homework write route, payload, or public client operation. The concrete POSTs shown in the session concern login and MFA, not homework or lesson data ([exports, lines 20-22](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/index.ts#L20-L22); [generic helpers, lines 198-204](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/session.ts#L198-L204); [login POST, lines 67-81](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/session.ts#L67-L81); [MFA POST, lines 121-142](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/session.ts#L121-L142)).

## Caveats and gaps

- There is no dedicated homework fetch, detail, or mutation API in the client. Consumers fetch the whole overview and select `homework` ([client, lines 230-235](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/client.ts#L230-L235)).
- The public homework object omits the raw `RowNumber` and exposes no stable ID, completion state, attachment, lesson-period link, creation/update timestamp, or explicit assigned-versus-due-date meaning. Those fields are absent from the recognized raw and public shapes ([raw shape, lines 43-57](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/parsers/overview.ts#L43-L57); [public shape, lines 129-137](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/types.ts#L129-L137)). Therefore consumers should not invent those meanings from `date`.
- Homework dates are not normalized by the homework parser; it copies `hw.Date` and sorts it lexically. The `YYYY-MM-DD` guarantee is a declared upstream type contract, dependent on Wilma's overview payload honoring it ([parser, lines 246-258](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/parsers/overview.ts#L246-L258); [type, lines 129-137](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/types.ts#L129-L137)).
- Lesson notes are HTML scraping and depend on Wilma table markup, colspans, `title` formatting, and `at-tpN` classes. Missing/out-of-grid timing becomes `null`; this is not a general lesson-diary or homework-detail API ([markup contract, lines 4-19](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/parsers/attendance.ts#L4-L19); [time and field extraction, lines 85-107](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/parsers/attendance.ts#L85-L107)).
- Pass an explicit date to `attendance.list`. The CLI documentation says omission defaults to today, but the current client sends no query and passes `""` to the parser; the parser then requires each row date to equal that empty target. Source inspection therefore indicates that omission can produce an empty result rather than today's notes (an inference, not live-Wilma verification) ([documented default, lines 70-75](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-cli/README.md#L70-L75); [client behavior, lines 203-215](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/client.ts#L203-L215); [exact-date filter, lines 20-48](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/packages/wilma-client/src/parsers/attendance.ts#L20-L48)).
- Upstream describes the project as an independent, unofficial reader, not Visma's official client, and says it reads schedules, homework, exams, grades, attendance/lesson notes, messages, and news ([README, lines 11-15](https://github.com/aikarjal/wilmai/blob/2ed3a3e48700f456918bb44f382311d10f3ba78c/README.md#L11-L15)). Tenant behavior can therefore vary beyond what these source-defined parsers cover.
